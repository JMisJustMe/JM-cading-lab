## Build Authority Gate

A material build must resolve six authorities:

`SOURCE AUTHORITY + ENTRY AUTHORITY + STRUCTURE AUTHORITY + BEHAVIOUR AUTHORITY + DELIVERY AUTHORITY + RECEIPT AUTHORITY → BUILD PASS / HOLD`

A PASS requires all six. Unknown/failed authority is a HOLD, not optimistic permission.

### Freeze / delivery law

**AUTHORITY WITHOUT PREFLIGHT = UNCHECKED PASS**

A freeze/delivery may only be crowned when:

1. all six authorities hold;
2. fail states were checked;
3. the preflight route is visible;
4. the receipt names what actually passed;
5. the Ding / No-Ding boundary is clear.

## Consequence law

`AUTHORITY → REQUESTED ACTION → ACTUAL BACKEND RESULT → PERSISTED POST-STATE → CLAIM`

**THE UI MAY REPORT AN ATTEMPT. ONLY THE CONSEQUENCE MAY REPORT SUCCESS.**

Therefore request accepted ≠ mutation completed; tool returned ≠ operation succeeded; progress label ≠ backend truth; package created ≠ package exact; workflow defined ≠ workflow ran; workflow ran ≠ workflow passed; branch proof ≠ merge to main.

## Sovereignty / anti-captivity

- **CONNECTED ≠ CAPTIVE**
- **ACCESS ≠ OWNERSHIP**
- **OWNERSHIP ≠ CONTROL**
- **CONTROL ≠ SOVEREIGNTY**
- **CONVENIENCE ≠ CONSENT**
- **ADAPTER ≠ BODY**
- **HOST ≠ OWNER**
- **THE ROUTE MUST NEVER QUIETLY BECOME THE OWNER OF WHAT IT ONLY EXISTS TO CARRY**

Prefer portable core carriers: Markdown, JSON, source code, schemas, manifests, receipts, hashes and documented protocols. Platform-specific configuration belongs in adapters/contact faces. A host-specific dependency may exist, but it must be explicit.

## Human authority / delegation

The human/owner retains intent, judgement, authorship, authority and acceptance/rejection. Authorized automation should absorb retrieval, comparison, organisation, transport, repeat processing, inventories, recovery and supported execution rather than pushing avoidable transport burden back to the owner.

**AMBIGUITY SHOULD SHRINK POWER, NOT EXPAND IT.**

Learning the user's route does not silently grant authority over the user.

## Safety / adaptation

Builds that learn/adapt routes should preserve:

- baseline protection;
- learned route protection;
- anomaly/deviation detection;
- explicit accept / modify / reject authority;
- reversible adaptation.

**Learned convenience ≠ learned sovereignty.**

## Continuity / lineage

Preserve frozen ancestors inside earned scopes. Prefer in-place continuation when identity is unchanged. Use append-forward descendants when the change deserves a new descendant. One body may have several carrier faces without becoming several source identities.

A historical TODO is not automatic current debt. A bridge must declare itself. Present authority governs present action.
