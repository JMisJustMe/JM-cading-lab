32_Cb

Positional Bridge Coding Body — 3 ↔ C, 2 ↔ B by letter placement.

CORE: 32_Cb is a dual-carrier bridge. The numeric rail 3,2 and alphabet rail C,b resolve to the same letter positions. The underscore _ is the bridge/check operator.
POWER: position and letter can carry the same route redundantly, so the code can translate and self-check.
BOUNDARY: numeric position does not determine case. 32 can recover CB, but the lower-case b in Cb is presentation metadata unless another rule explicitly gives case a function.

32_Cb Laws

    
    
      
  1. POSITION BEFORE ASSUMPTION. In POSITION mode, A=1 … Z=26.
    2. 
      
  2. BRIDGE MUST MATCH. Left and right rails must resolve to the same position sequence.
    3. 
      
  3. CASE ≠ POSITION. Case is preserved but not invented.
    4. 
      
  4. COMPACT ≠ AMBIGUOUS. Bare digit strings are single digits; 10–26 use separators/brackets.
    5. 
      
  5. SAME MARK ≠ SINGLE FUNCTION. Position, numeric, sound and route readings stay separate until a layer is declared.
    6. 
      
  6. MESH ≠ MERGE. 32_Cb can interoperate with Cading, FlowTalk and JM32 without swallowing them.
    7. 
      
  7. TRACE BEFORE CROWN. A bridge PASS must show both resolved rails.
    8. 
      
  8. BUGG IS ROUTE INFORMATION. A mismatch reports where the rails diverge.
    9. 
      
  9. REVERSIBLE WHEN POSSIBLE. Position↔letter conversion should round-trip under the same alphabet profile.
    10. 
      
  10. NO DING, NO CLAIM. Validated relation earns DING only inside its stated layer.
