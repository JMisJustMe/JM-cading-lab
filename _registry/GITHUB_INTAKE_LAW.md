# JM GitHub Intake Law

Status: active
Repo: `JMisJustMe/JM-cading-lab`

## Corrected rule

The old wording was wrong:

> Put them into GitHub yourself once, then I can work with them there.

The corrected JM law is:

> The user makes the body available through upload, paste, File Library, Zionfolder zip, or existing GitHub route. The assistant handles GitHub staging, structure, registry updates, and repo pushes wherever the connector permissions allow.

## Route states

Every build/file/body must be marked honestly:

- `local_only` — visible or known on device, but not accessible to the assistant yet.
- `seen_in_video` — visually confirmed by screenshot/video, but file body is not accessible yet.
- `available_here` — uploaded/pasted or accessible in File Library.
- `github_staged` — placed into repo intake/registry structure.
- `github_active` — part of a usable repo route.
- `demo_ready` — can be opened/tested through a working route.
- `monetisation_candidate` — polished enough to consider product/demo/client route.

## No fake doors

A file name, screenshot, or video proves existence signals, not file access.

Do not create working Open links unless the body is actually present in GitHub, bundled in a Zionfolder, embedded in a singular-link HTML, or otherwise accessible through a proven route.

## GitHub role

GitHub is the version rail, proof shelf, intake structure, and public/private route manager.

Zionfolder remains the body package.
Single-link HTML remains the quick open/demo door.
Ehilatheo remains the phone-side mobile build cockpit.
