# JM-operated Host — CP01 portable delivery adapter

An **additive capability recipient** of the existing JM Sovereign Agent / Universal Host Adapter Conformance lineage. Does **not** replace JM CLOUD CONTACT SERVER, Build Mesh, Cloudflare, Render, or the Estate public site.

Node 20+; no third-party dependencies. Store runtime/release files outside the public GitHub repository, under owner-controlled filesystem permissions.

* Deploy: `node host.mjs deploy jm-cloud-contact ./prepared-public-site /private/jm-store`
* Inspect: `node host.mjs inspect jm-cloud-contact /private/jm-store`
* Serve: `node host.mjs serve /private/jm-store`
* Rollback: `node host.mjs rollback jm-cloud-contact /private/jm-store`
* Local static delivery: `http://127.0.0.1:8795/apps/jm-cloud-contact/`
* Read-only health: `http://127.0.0.1:8795/_jm/ready`
* Test: `node --test host.test.mjs`

Features: content-addressed release manifests, per-file integrity checks, atomic active pointers, verified rollback, symlink/traversal refusal, read-only HTTP, bounded input, repeatable release state and readback. Local CLI-only mutation. Default listener is loopback. `JM_HOST_ALLOW_LAN=1` is explicit *insecure LAN HTTP*, not safe internet deployment.

**Proof boundaries:** prepared static files only. Does not yet execute arbitrary apps, host Cloud Contact's dynamic `/v5` API, perform managed TLS, load balancing, tenancy, cross-machine locking, off-site backups, autoscaling, build containers, or public deploy. It is not full Render parity. Do not expose HTTP to the Internet. Host state and backup reliability require independent examination before replacing services. Existing host adapters remain unaffected. Recipient test proof does not transfer from donors.

## CP02: native dynamic Node-process contact

`supervisor.mjs` is a second **local host adapter**. It can launch a pre-existing Node entrypoint unchanged, request loopback binding through HOST/PORT, poll an existing `/ready` endpoint, restart an unexpectedly exited child (bounded), and stop the child. Example for an existing local JM Cloud Contact source with its own secrets already provisioned *outside GitHub*: `node supervisor.mjs run ./JM_CLOUD_CONTACT_SERVER_v0_4_2.mjs 8791 .`.

The server's own `JM_CLOUD_ADMIN_TOKEN`, `JM_CLOUD_SERVER_SECRET`, data path and origin allowlist are still required and are **not** generated by this adapter. Never run an untrusted entrypoint; the process runs with the invoking user's permissions. This is **not** a sandbox or a public multi-tenant PaaS. No local Cloud Contact v0.5 graft or real remote host has been certified. Test: `node --test supervisor.test.mjs`.

## CP02 security review delta

Static release reads/deployment now reject symlinks in store ancestors and refuse a private store nested under the public source. HTTP integrity failures return a fixed diagnostic without exposing local paths. Private directories must remain owner controlled; these checks do not provide an atomic filesystem sandbox against a malicious same-user process. Static CLI mutations still require a single operator; cross-process deployment locking is OPEN.

The supervisor checks that its port is unoccupied before the initial spawn, validates bounded startup timeouts, refuses symlinked entry ancestors and duplicate starts, bounds readiness bodies to 16 KiB, and observes child close events, including spawn failures. A readiness result is accepted only while the same tracked child remains active. The port is released before spawning: this prevents the reproduced pre-existing-listener false positive but cannot cryptographically attest which process answers or eliminate a malicious local port race. HOST/PORT are cooperative settings, not enforcement against a server that ignores them. Run only trusted existing service code. Process isolation, authenticated readiness, post-start health-driven recovery, descendant process-tree shutdown, persistent logs and remote host proof remain OPEN.

### CP03 preflight recovery

An occupied local port is a **pre-spawn refusal**. Once that listener is released, the *same* `JMNodeSupervisor` instance may retry `start()`; concurrent calls during preflight remain refused. This does not relax port-race, process-identity or public-deployment limits. A started or explicitly stopped instance is not automatically reset for reuse. See `hardening.test.mjs` for the actual occupied → refused → released → ready test.

### CP04 opt-in cooperative readiness proof

The pre-existing readiness check accepts a local JSON response from the expected port but cannot prove that the responder is the supervised child. CP04 adds an **optional** per-spawn challenge, without changing the default behavior of older JM services.

For a trusted existing Node service that supports the challenge, construct `new JMNodeSupervisor({entry, cwd, port, readinessProof: true})`. The supervisor passes a freshly generated 48-character hex value to that child in `JM_SUPERVISOR_PROOF`; the service must include `supervisorProof: process.env.JM_SUPERVISOR_PROOF` in its existing successful JSON `/ready` response, alongside `ok: true` and `ready: true` (or the existing `JM_NODE_TEST` scope). The supervisor rejects missing/wrong values, rotates the challenge on every restart, and does not include it in `status()`. Do not log, store or publicly return the challenge outside the loopback readiness response. The CLI's existing default remains unchanged.

This is **cooperative readiness evidence**, not process identity attestation, authenticated TLS, a privilege boundary or a safe Internet control endpoint. A hostile process with access to the child environment or loopback traffic may still obtain the challenge. Enabling this option against an existing service that does not echo the challenge deliberately produces `SUPERVISED_READINESS_HOLD`; do not enable until that service supports the contract. The child must still be trusted and deployed through its existing owner-controlled source route.

Test: `node --test proof.test.mjs`. Tests cover default compatibility, correct challenge, bad/missing challenge refusal, injected-environment override, rotation after crash, status non-disclosure, and inherited CP03 occupied-port retry. External host deployment, physical Fold acceptance, managed TLS and cross-machine persistence remain OPEN.
