# Counterpart Perfection Architecture — v2.4.0

## Governing route

`PROVEN SOURCE → PRESERVED SNAPSHOT → CAPABILITY AUDIT → GOVERNED ADAPTER → TARGET BODY → TEST → DING → QUEUE CUSTODY`

## Strengthened organs

### Container-aware JMvisusual shell
The forge reads the width of its own workspace, not only the browser viewport. This fixes the cramped laptop/desktop route where three inner columns were forced into a narrow right-hand deck.

### Capability audit
Every pairing now exposes:

- direct matched contracts;
- explicit unresolved adapter obligations;
- compatibility percentage;
- three strongest source candidates for the selected target.

The UI preserves **CAN-BE ≠ IS** by showing missing obligations instead of hiding them behind a high-level score.

### Serialized build contact
Probe, Build, Test and combined Build + Test + Ding share an action guard. A rapid double contact emits one queue body rather than duplicate receipts.

### Matrix navigation
Every one of the 80 compatibility cells is clickable and keyboard-operable. Selecting a cell routes both its source and target into the active forge.

### Queue custody
Built counterparts receive local Load Route and Remove actions. Loading restores source, target, mode and identity without modifying the preserved source organ.

### Observation
Generated bodies expose active format, line count and byte size. Receipts use live status semantics; dynamic choices publish pressed/selected state.

## Coding-body strengthening

- **Cading:** emitted body remains the authoring source.
- **JM32-1DA Governance:** strict mode and LIMIT obligations stay explicit.
- **PrimeBody:** source, target, handoff and compatibility remain separate bodies.
- **FormeULA:** compatibility is calculated from declared capabilities/needs.
- **JMLogic:** source selection, target selection, handoff mode and test gate are ordered.
- **Visualang:** matrix, route field, capability chips and progress rail expose the route.
- **GripCube:** v2.4 UI state stays distinct from v2.3 project state.
- **CadenVM / RouteOS:** Native projection and host lifecycle remain tested.
- **CodeHand:** manifest, Cading, JavaScript and contract bodies remain exportable.
- **TraceBox / Ding:** action, test, warning and recovery receipts remain visible.
