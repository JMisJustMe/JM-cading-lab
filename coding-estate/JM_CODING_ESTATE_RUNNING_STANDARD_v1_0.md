## Crown boundary

This standard converts the current **64-body role-qualified Coding Estate** into an actual operating floor for builds and agents.

It does **not** mean:
- every build must execute all 64 bodies;
- every body has identical jurisdiction;
- a donor's proof transfers to a recipient;
- the historical 100/105 engineering-equalisation/parity registers are redefined as 100/105 literal current coding identities;
- the 44 adjacent/non-code engineering organs are silently promoted into the coding count;
- all 64 are product-final, self-hosted, owner-device crowned or universally portable.

**MEMBER OF X HOUSE ≠ IS AN X.**  
**MESH ≠ MERGE.**

## Running law

For every material coding/runtime/OS/engine build:

`RECOVER CURRENT AUTHORITY → LOAD CURRENT-64 REGISTRY → MATCH TASK PRESSURE → SELECT SMALLEST RELEVANT BODY/DONOR SET → PRESERVE IDENTITY → BUILD/CHANGE → EXECUTE/CONTACT → READ BACK → PROVE RECIPIENT → TRACE → DONATE LEARNING`

The full 64-body set is the **available sovereign capability field**. Selection is relevance-driven, not ceremonial.

### Mandatory standards

1. **All 64 are visible to routing.** A compatible builder/agent must not behave as though only the familiar flagship bodies exist.
2. **Use the smallest sufficient donor set.** Do not invoke bodies merely to claim inclusion.
3. **Recover before rebuild.** Existing current bodies and organs outrank duplicate reinvention.
4. **Proof does not transfer by name.** Receiver contact earns receiver claims.
5. **Source-truth states stay visible.** Recovered historical source, reconstructed descendants, current-native maturation and new founding bodies are not interchangeable provenance.
6. **Host ≠ owner.** Platform/toolchain choice may change contact capability, not body identity or ownership.
7. **Runtime proof is typed.** Syntax, unit, runtime, host, recipient, device, owner/lived-contact and release/deployment proofs remain distinct.
8. **Android-first; laptop-conjoined where relevant.** Device parity is a build concern, not an afterthought.
9. **Full Body → Straight Run → Correct After.** Avoid fragment-polish loops that prevent a working body from standing.
10. **Donate learning back.** A newly proved mechanism becomes available to relevant Estate bodies without flattening identity.
