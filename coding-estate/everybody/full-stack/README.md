## Governing correction

`body source → parser → AST → semantic gates → portable lowering → runtime → trace → Ding`

That is not the same claim as giving every body its own complete language/toolchain/OS stack. The earlier `10 / 10` label is therefore bounded to **canonical-native v2 conformance only**. It must not be read as full parser/compiler/SDK/kernel parity.

The new estate-wide target is stronger:

## Individual and collective law

### Individual lane

Every body must be buildable, testable, executable and inspectable by its own ID. Its syntax, diagnostics, IR nodes, SDK namespace, package name, kernel personality and receipts must retain that identity.

### Collective lane

All bodies may share proven organs through explicit adapters:

`Body-native source → Body AST → Body IR → OneBody exchange boundary → target/runtime/kernel`

The collective layer may coordinate bodies, but it may not silently rename them, merge incompatible laws, erase provenance, or make the shared host the source authority.

## Kernel meaning

Full parity does **not** mean copying one handwritten x86 kernel one hundred times and calling the copies sovereign. It means:

- each body owns a body-specific kernel blueprint/personality and kernel-visible identity;
- each can generate a bounded bootable kernel carrier from the proven RouteOS kernel factory;
- each can also run as an isolated RouteOS user body through PermissionGate, RouteScheduler, FaultHold and RecoveryBody;
- the collective image can register multiple bodies without erasing their separate source, state, permissions, faults or traces.

A body is not marked **HARD_KERNEL_PASS** until its generated image has compiled, booted and passed the declared QEMU trace gates. A generated blueprint alone is not a kernel Ding.
