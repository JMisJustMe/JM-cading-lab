# Cading / Quadze Functioning 100 Standard v0.1

Status: GOVERNING ELEVATION GATE — NOT A CROWN

## Correction

The generated full-stack factory proved that the first 100 registered coding bodies could each receive a parser-shaped frontend, IR-shaped lowering, SDK namespace, target emitters and kernel-source package.

That is useful factory proof, but it is not sufficient evidence that all 100 are functioning bodies at Cading or Quadze standard.

A copied shell, renamed grammar, identity manifest or generated kernel office is not individual functional consequence.

## Immediate priority

Post-100 admission remains open in principle, but engineering priority now stays on the first 100 until they possess functioning body-native execution.

JaggedMirror remains preserved as admitted Body 101. No newly recovered body is to distract from the elevation of the first 100.

## Functioning-body gate

A body reaches `CADING_QUADZE_FUNCTIONING` only when all of the following are demonstrated:

1. its own stable identity, law and source namespace;
2. a body-native current-canon source or input form;
3. parsing or equivalent input interpretation;
4. an explicit AST, event graph or equivalent structured representation;
5. body-specific semantics rather than name substitution;
6. specialist IR or executable instruction form;
7. actual runtime consequence and visible state change;
8. execution of at least one capability belonging to that body;
9. rejection of cross-body source substitution;
10. fault capture and a declared recovery route;
11. deterministic trace and receipt output;
12. a usable output, package, tool, state, visual, decision, game consequence or other result appropriate to the body.

## Native-form boundary

Text languages require source syntax, parser, semantic rules and runtime.

Gesture, contact, speech and embodied bodies require temporal/event grammars, state models, ambiguity or noise handling, runtime adapters and accessibility alternatives.

Visual bodies require an input/render/state/feedback route.

Compiler bodies must actually transform source structure.

Runtime and VM bodies must actually load and execute state-changing instructions.

Game bodies must actually advance game state.

Governance and proof bodies must actually accept claims/evidence, gate them and produce hold/pass consequences.

Delivery bodies must actually manifest, hash, package and restore.

Containers and houses must actually register, isolate, select and coordinate bodies without swallowing identity.

No body receives fake text syntax merely to satisfy a checklist.

## Shared-organ law

Shared parser, runtime, VM, emitter, RouteOS, test, receipt and delivery organs are permitted.

Shared organs do not reduce sovereignty when:

- the source namespace is body-owned;
- the accepted operations are body-specific;
- semantics produce body-appropriate consequence;
- cross-body substitution is rejected;
- trace and fault identity remain attached to the originating body.

## Current milestone ladder

- `GENERATED_EQUIPMENT`: package and organs exist.
- `PORTABLE_FUNCTIONING`: source/input executes semantics and state change through the shared portable machine.
- `EXACT_NATIVE_RECOVERED`: historical or authoritative native form is recovered and conformance-tested.
- `INDEPENDENT_RUNTIME`: body runs outside the generic portable host.
- `INDEPENDENT_MACHINE_DING`: body receives its required kernel/device/machine proof.
- `SELF_HOSTING_OR_EQUIVALENT`: body can materially produce, extend or govern itself where appropriate.
- `FEDERATED`: body cooperates without identity collapse.
- `FROZEN_CROWN`: every required gate for that body's role is earned and receipted.

## Claim boundary

Passing the portable functioning gate does not claim:

- exact historical syntax where it has not been recovered;
- a separate machine kernel Ding;
- full self-hosting;
- production maturity;
- P9 freeze or crown.

> Cading and Quadze are the functional floor. Every body must then become more completely itself.
