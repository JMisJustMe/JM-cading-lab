# JMISJUSTME — Freestanding Website + APK Foundation v1

## Crowned direction

The primary product is a proper JMISJUSTME website standing on its own custom domain.

The constant secondary product is a proper Android APK built from the same living JM source body.

GitHub and Cloudflare may remain useful behind the scenes. They are support rails, not the public identity, destination, landlord or product name.

## One source, two delivery bodies

```text
JM bodies + registries + assets + route laws
                    |
          shared host-independent core
             /                    \
custom-domain website      native Android shell
```

The APK is not defined as a browser shortcut or an afterthought conversion. It must become a signed installable Android application with an owner-controlled package identity, native back handling, file routes, sharing, downloads, offline proof and a build receipt.

## Current foundation move

1. Correct public wording that crowns a support host.
2. Keep internal routes relative and host-independent.
3. Publish the platform contract at `platform/jm-platform-contract.json`.
4. expose `JM.NativeBridge/1.0` in the existing website runtime.
5. Cache the contract and shared runtime in the service worker.
6. Keep the package ID unlocked until its application identity is deliberately crowned.
7. Connect the custom domain without changing the Estate's internal structure.
8. Build the Android shell against the same route and registry truth.

## Website gate

The website is ready to be called freestanding only after:

- the custom domain is connected;
- visible GitHub, Cloudflare and builder identity has been removed from the public-facing shell;
- mobile and desktop routes are proven;
- install and offline behaviour are proven;
- the owner can export a current recovery receipt.

## APK gate

The Android body is ready to be called proper only after:

- its package ID and signing custody are crowned;
- an APK/AAB builds successfully;
- it installs and opens on the OPPO Find X5 Pro;
- Android back, files, share, downloads and external-link boundaries work;
- a usable offline core survives loss of the delivery host;
- the website and APK report matching registry/body versions.

## Standing law

> Website first. APK always in view. One living source line. No second rebuild.
