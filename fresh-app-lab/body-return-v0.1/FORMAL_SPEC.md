# BUILT ENOUGH: BODY RETURN — Formal System v0.1

## Governing statement

> I’ve built enough. Now something needs to come back into my life.

## System law

**Numbers guide the shape. The body sets the boundary. Use supplies the proof.**

## What SHIMS does here

SHIMS is the interpretive and comparative layer. It applies the user's logic to existing pattern systems and real-world body information. It does not treat numerology, BMI, body weight, age, public-health guidance, or any single measure as absolute authority.

## Three information lanes

1. **Symbolic lane** — date of birth and optional favourite number generate a personal signature, sequence and rhythm.
2. **Body lane** — present comfortable capacity, chosen movements, symptoms and perceived exertion set the actual dose.
3. **Receipt lane** — completed actions, mood, exertion, symptoms and notes determine what changes next.

The lanes are combined but not confused.

## Claim discipline

Every statement should be tagged as one of:

- **Symbolic:** a meaning or structure generated from number/date patterns. No medical causation claimed.
- **Personal:** an observation about one person under stated conditions.
- **Guideline:** general public-health context, not an individual diagnosis or prescription.
- **Mechanism hypothesis:** a proposed explanation that remains open to comparison and revision.

The question is never merely “Is there evidence?” It is:

> Evidence or receipt for which claim, for whom, under what conditions, and for what use?

## Input model

Required:
- date of birth
- comfortable push capacity
- comfortable core capacity
- comfortable walking duration
- preferred effort
- at least two movement lanes

Optional:
- name or alias
- favourite number
- height
- weight
- limitation/concern flag

## Signature model

- **Birth code:** `DD·MM·R`, where `R` is the digit sum reduced while preserving 11, 22 and 33.
- **Anchor:** favourite number when supplied; otherwise birth day.
- **Year pulse:** reduced year digit sum.
- **Movement count:** derived from birth month, bounded to 2–4.
- **Rounds:** derived from the signature root, bounded to 1–3.
- **Rest interval:** derived from year pulse, bounded to 30–75 seconds.

These values shape the routine. They do not override physical capacity.

## Capacity model

The first version uses a fraction of the user’s stated comfortable capacity:

- very gentle: about 30%
- gentle: about 40%
- steady: about 52%
- challenging: about 62%
- hard: about 72%

A concern/inactivity flag reduces the starting factor further. The generated dose never intentionally exceeds the user's stated comfortable capacity.

## Adaptation loop

After each completed session:

- RPE 1–5, no pain: increase next factor slightly.
- RPE 6–7, no pain: maintain.
- RPE 8–10, no pain: reduce slightly.
- pain or worrying symptoms: reduce, choose easier variations, rest and consider professional advice.

This is a conservative self-observation rule, not a medical treatment protocol.

## Game layer

The MVP includes:
- XP for completion
- levels
- daily streak
- future territories: Foundation → Rhythm → Capacity → Return

The game rewards participation and receipts, not punishment, extreme intensity, weight loss or body comparison.

## Route to return

2. Documented method — every session creates a receipt.
3. Early users — test personalised transfer.
4. App system — automate generation, logging and adaptation.
5. Game layer — make progress visible and engaging.
6. Paid product — charge for useful personalisation, structure and continuity.
