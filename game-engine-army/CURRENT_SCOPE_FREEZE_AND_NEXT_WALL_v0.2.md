# JM Game Engine Army — Current-Scope Freeze and Next Wall v0.2

## Earned current scope

Nine distinct browser-first bodies now exist behind separate source, semantics, receipts and delivery routes:

1. GlyphPlay — creator/stage/playtest.
2. GameForge — game-body build graph and cartridge compilation.
3. GlyphForge — asset, physical-input and adapter forging.
4. PLAYFORM — repeatable playable-expression proof.
5. JM GameCore — identity-preserving shared runtime services.
6. JM GAME NATIVE CORE — deterministic fixed-step runtime and target ABI contracts.
7. Kading Game Estate Engine — Kading source, AST, Game IR and interpreter.
8. JM Game Engine Console — operator surface without engine ownership collapse.
9. Army Federation — seven-stage handoff and coding-body difference trials.

The integrated gate rebuilds all nine, reruns their semantic tests, verifies nine unique output hashes, builds one phone/laptop launcher, and seals the editable bundle.

## The five max pushes

### Push 1 — JM GameCore

`BodyRegistry → ServiceBus → namespaced state → trace → snapshot → recovery → host packet`

Different engines use shared offices without sharing state identity.

### Push 2 — JM GAME NATIVE CORE

`profile → deterministic fixed step → collision/consequence → FaultHold → RecoveryBody → target ABI`

C++17, Rust 2024 and Wasm32 are emitted as explicit ABI contracts. Native binaries are not yet claimed.

### Push 3 — Kading Game Estate Engine

`Kading source → AST → Game IR → repeated runtime events → receipt`

Malformed operations and missing required declarations are rejected.

### Push 4 — JM Game Engine Console

`select → launch → service request → snapshot/recover → engine-owned receipt`

The console operates engines; it does not become them.

### Push 5 — Army Federation and Coding-Body Trials

`GlyphForge → GameForge → GlyphPlay → PLAYFORM → Kading → NativeCore → GameCore`

The game identity remains fixed through all seven offices. Cading, Quadze, RECORP, FlowTalk and FormeULA produce distinct route hashes for that same game identity.

## Failed route retained

The first v0.1 GitHub package reconstruction failed because one manually transferred binary-text segment was clipped before semantic testing. The engines were not weakened to accommodate it. The route was replaced by source-visible modular v0.2 files and direct CI tests.

**A failed route was not treated as a failed task.**

## Exact next wall

The following remain genuinely open:

- user-side phone and laptop editing/play contact;
- sustained save/edit/export/import cycles on real projects;
- native C++/Rust/Wasm binaries rather than target contracts;
- richer graphics, audio, assets and performance profiling;
- self-hosting or meaningful body-native equivalents;
- exact recovery of still-missing historical source bodies;
- independent final polish and crown decisions per engine;
- Dragon Mirror's strongest editable source attachment and engine/game lineage split.

No final engine crown is claimed at this boundary.
