# Wix Reconstruction Page and Content Map v1.0

## First-view law

The first mobile viewport must answer four questions without scrolling through a maze:

1. **Whose Estate is this?** — Theodore Benjamin Scott / JM / JMISJUSTME.
2. **What is it?** — a living, governed body of original works, tools, theories, apps, games, engines, languages, records and public routes.
3. **Where do I go?** — clear doors to Explore, Use, Read, Play and Verify.
4. **What is current?** — the three present authority heads and their proof state.

No tiny-box wall. No unexplained initials. No decorative control that looks operational but does nothing.

## Primary navigation

### 1. OPEN FIRST

Purpose: identity, orientation, current authority and strongest public entry routes.

Required organs:
- owner/originator statement;
- one-sentence Estate explanation;
- current-head strip;
- five large mobile doors: **Explore / Use / Read / Play / Verify**;
- visible claim boundary: public access is not the whole private Estate.

### 2. ESTATE MAP

Purpose: show the Estate as related houses and routes rather than one giant undifferentiated list.

Public house groups:
- Apps and usable tools;
- Games and game engines;
- Coding bodies, languages, runtimes and operating systems;
- Theories, formulas and prediction-bearing bodies;
- Author, lyrics, manuscripts and outward works;
- Websites, portals and public delivery routes;
- Governance, registers, receipts and proof.

Every house card must state:
- what lives there;
- what can be opened now;
- strongest current body;
- proof/maturity status;
- route back to the map.

### 3. COMMAND ROOM

Purpose: controlled access to the current registers.

Seats:
- JM Master Tool Register v2.0;
- JM Register of Registers v1.0;
- JM Command Register v1.0 — First Pass Finished.

The full interactive Command Register becomes a public door only after its separate exact-carrier PR, merge, deployment contact and JM physical test. Until then, show it as **proved proposal / not yet public authority**.

### 4. USE

Purpose: surface genuinely usable bodies before archive depth.

First lanes:
- JM Reader / routing brain;

- signal/studio bodies;
- device-safe tools;
- downloadable or openable packages with honest platform labels.

Each usable body needs:
- Open;
- What it does;

Arena/control loop belongs in the first viewport. Deep notes, editors and exports sit behind tabs or drawers.

### 6. READ

Purpose: theories, formulas, manuscripts, author bodies and explanatory works.

Reading routes:
- reality, causation and contact;

A reading card must distinguish:

### 7. VERIFY

Purpose: make proof visible without forcing visitors into repository archaeology.

Required organs:
- current authority heads;
- version/date;
- SHA or receipt where useful;
- passed counts and disclosed residual blockers;
- live-contact status;
- explicit distinction between repository proof, deployment proof and JM physical Ding.

### 8. OWNER / RETURN

Purpose: authorship, ownership, contact and route back.

Carry:
- Theodore Benjamin Scott / JM / JMISJUSTME as principal originator, governor and creative director;
- public biography route;
- contact form already supported by Wix Forms;
- return-to-OPEN-FIRST button;
- no vendor branding presented as Estate identity.

## Responsive and visual laws

- Android-first; laptop-conjoined.
- Minimum tap targets suitable for phone use.
- Horizontal rails only where labels remain fully readable.
- Large room titles; plain-language subtitles.
- One dominant action per room.
- Avoid excessive vertical scrolling; use drawers/tabs for depth.
- Preserve a consistent home/map/verify rail.
- Visual richness must never hide route state.
- Public links open the public body; governance links open the receipt, not an unexplained raw file list.

## Publication gate

The rebuild branch may be previewed and physically tested. It must not replace the published Wix branch until:

1. all main doors open;
2. phone layout passes;
3. no stale/false authority labels remain;
4. Command Register route matches its actual merge/deployment state;
5. Wix preview is inspected by JM;
6. JM explicitly authorises publication.

Publication is not Ding. Ding requires a separate explicit JM statement after physical contact.
