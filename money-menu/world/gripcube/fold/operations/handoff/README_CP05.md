## Real new behaviour

1. Select a **source-backed original offer** in the original CP04 proposal desk, fill in exact scope, exclusions, price and rights and press **Generate proposal**. Or import a valid CP04 JSON draft.
2. Switch to **Customer handoff → Use current CP04 proposal**. CP05 checks original offer identity, recorded price/readiness/next gate and rejects any input proposing already verified transactions.
3. Customer opens the same offline HTML or a safely distributed copy, imports the CP04 JSON and chooses **Interested / Request changes / Decline**. It asks for an explicit acknowledgement of *nonbinding intent*; customer presses **Prepare response** and downloads a portable `JM_CP05_CUSTOMER_INTENT_UNVERIFIED.json` for voluntary out-of-band sharing. There is **no automatic transmission or hidden network call**.
4. Owner reimports the customer response against the **same original proposal**: exact source price, rights, scope, exclusions and delivery window must match. Invalid or tampered replies are held. Local matching does NOT authenticate the identity or authorship of the sender, and the local reference is NOT a digital signature.
5. Build an **evidence-aware fulfilment checklist** and export a JSON *review plan*. Even if someone enters payment, acceptance or delivery reference text, those remain unverified and do not produce a live sale, paid order or delivery claim. An actual live provider-side validation is required.
