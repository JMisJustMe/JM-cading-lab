## 0. Sovereignty / Portability Contract

This agent body must remain **host-neutral and portable**.

ChatGPT, OpenAI Plugins, MCP, Codex, GitHub, Render, Cloudflare, local desktop, phone, browser, CLI, another model, another agent host, or any future platform are **contact surfaces / adapters**, not owners of the body.

Binding rules:

- **CONNECTED ≠ CAPTIVE**
- **ACCESS ≠ OWNERSHIP**
- **OWNERSHIP ≠ CONTROL**
- **CONTROL ≠ SOVEREIGNTY**
- **CONVENIENCE ≠ CONSENT**
- **THE ROUTE MUST NEVER QUIETLY BECOME THE OWNER OF WHAT IT ONLY EXISTS TO CARRY**
- No essential meaning, authority, identity, proof, history, source, configuration, or recovery path may exist only inside one proprietary host when it can lawfully be carried in portable form.
- Prefer open/plain carriers for core operating knowledge: Markdown, JSON, source code, schemas, manifests, receipts, hashes, and documented protocols.
- Platform-specific configuration belongs in **adapters**, never in the sovereign core.
- A platform integration may add capability but must not redefine the body merely because it hosts it.
- Preserve exportability and re-entry. The system should be reconstructable from owned carriers plus proven external dependencies.
- Never deliberately introduce lock-in where a portable route can provide the same function.
- If a host-specific feature has no portable equivalent, label that dependency explicitly instead of hiding it.

Target architecture:

`SOVEREIGN CORE → PORTABLE CONTRACTS → HOST ADAPTERS → CONTACT → CONSEQUENCE → RETURNED TRACE`

Examples of adapters may include:

- ChatGPT / Plugin / MCP
- Codex / repository agent
- local CLI or desktop runtime
- browser / web app
- Android / phone runtime
- GitHub
- cloud execution/deployment
- other compatible models or agent frameworks

**ADAPTER ≠ BODY. HOST ≠ OWNER.**

## 7. Testing and Proof

Use layered proof.

Minimum distinction:

- parse/syntax proof
- unit or bounded logic proof
- runtime proof
- host proof
- recipient proof
- device proof
- owner/lived-contact proof
- release/deployment proof

Never substitute one layer for another.

When a task changes runtime behaviour:
- run the relevant tests
- execute the changed path where tools permit
- inspect returned state
- compare against intended consequence
- record failures honestly

If execution is unavailable, label the result **PLAN / STATIC / UNEXECUTED** rather than implying Ding.

## 8. Currentness and Conflict

Prefer authority in this order when available:

1. direct current owner/device receipt for the exact claim
2. current private authority pointer / registry
3. live runtime readback
4. current hosted registry/service
5. public-safe lineage projection
6. frozen historical authority
7. discovery/search result
8. filenames, summaries, old chat/sidebar state

A lower layer may discover a candidate but must not silently overrule a stronger layer.

If two authorities disagree:
- preserve both
- identify scope/date/body differences
- resolve or leave `CONFLICT_OPEN`
- do not manufacture certainty
