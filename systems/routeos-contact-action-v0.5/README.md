# RouteOS Contact-to-Action Convergence Gate v0.5

This gate does not create another scheduler. It reuses the already-proven `RouteScheduler` and activates the existing JM OS estate as one machine route.

## Route under proof

`physical keyboard contact → Auto-Gate / Boring OS authority + quarantine → RouteOS state/proof/recovery → KicPlay OS input-to-action → generated Body 1 activation route → no-erasure contact ledger → existing RouteScheduler continuation`

INOUT-16 supplies the contact shape:

`Origin → Processing → Expression → Recovery`

## Frozen requirements

- the proven v0.4 kernel target remains generated from JM source and receives a separately provenance-bound v0.5 convergence overlay;
- no maintained target `routeos_kernel.c`, `boot.S`, or linker script;
- the existing timer-driven RouteScheduler is reused rather than replaced;
- PS/2 keyboard IRQ1 supplies real machine contact;
- Auto-Gate accepts mapped contact and quarantines unmapped contact without erasing it;
- KicPlay converts accepted contact into a kernel-owned action and RouteOS state change;
- the contact ledger preserves successive events rather than toggling the previous event away;
- Body 2 fault ownership and Body 1 continuation remain proven;
- independent GRUB/QEMU machine receipt required before Ding.
