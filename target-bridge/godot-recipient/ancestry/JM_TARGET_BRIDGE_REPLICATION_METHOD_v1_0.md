## 1. Recover before rebuild

Before any new host or source pass:
1. recover the current Target Bridge head;
2. recover the exact current source body;
3. recover any already-earned source adapter and host emitter;
4. recover runtime receipts and prior return deltas;
5. do not repeat an already-earned build/host proof unless the source, host or proof question materially changed.

RECOVER BEFORE REBUILD.

## 2. Exact-source custody

Every existing JM source entering Target Bridge receives a passport:
- body identity;
- canonical source filename/identity;
- exact SHA-256;
- version/current-head identity where known;
- source authority = JM;
- adapter status;
- unresolved/HOLD semantics.

The adapter activates only for the registered source identity/hash or another explicitly authorised equivalent.

SOURCE RECOGNISED ≠ SEMANTICS INFERRED.

If source bytes change, an older adapter does not silently inherit authority.

## 3. Source-supported semantics only

For each bounded semantic:
- semantic ID;
- trigger/input;
- entity/state affected;
- expected consequence;
- initial value if relevant;
- expected delta/clamp/consumption;
- runtime observation required.

Anything not established by source contact stays HOLD.

NO BUILD FROM INFERENCE.

## 5. Semantic execution plan

Compile the bounded source behaviour into a host-neutral plan containing:
- body ID;
- source hash/passport;
- semantic IDs;
- entities;
- input bindings;
- state variables;
- transitions/deltas;
- expected observations;
- unresolved HOLDs.

The plan is a bridge contract, not a replacement ontology for the game.

## 6. Host-ingestible emission

HOST ADAPTER READY ≠ HOST-INGESTIBLE BODY READY.

The bridge must emit the actual body/project a host can ingest:
- GDevelop: valid GDevelop project JSON/direct-editor carrier;
- Unity: valid Unity project structure with Assets/, Packages/, ProjectSettings/ and runtime harness;
- Unreal: valid .uproject + module/source carrier or another later-earned carrier;
- other hosts: their actual native/import format once earned.

Do not make the creator manually recreate scenes, objects, scripts or events to compensate for an incomplete emitter.

BRIDGE CONTACT MEANS THE BRIDGE CARRIES THE BODY ACROSS.

## 7. Static/local QA

Before host contact verify:
- source passport matches;
- semantic plan compiles;
- host files exist;
- required semantics are represented;
- HOLDs remain HOLD;
- receipt schema exists;
- unsupported/native-emitter claims are refused;
- no host gains real-runtime PASS from static generation.

HOST-INGESTIBLE BODY READY ≠ REAL-HOST DING.

## 8. Proven host delivery routes

### GDevelop

1. Commit generated GDevelop project JSON to GitHub.
2. Feed its raw GitHub URL into GDevelop's editor project URL.
3. Open/Preview.
4. Perform only declared bounded actions.
5. Observe instrumentation.
6. Write runtime receipt.

No manual reconstruction.

### Unity

Live contact established the reliable route:

1. identify the exact generated Unity branch/commit;
2. clone the exact ref into a fresh unique directory:
   git clone --branch <EXACT_BRANCH> --single-branch <REPO_URL> <NEW_DIRECTORY>
3. verify the local fileset matches the requested ref;
4. Unity Hub → Add project from disk;
5. open with the declared installed editor version;
6. let Unity compile;
7. do not manually build the scene; runtime harness mounts itself;
8. Play and perform the declared bounded actions;
9. observe the runtime receipt/banner.

Contact-produced rule:

REQUESTED REF ≠ VERIFIED LOCAL CHECKOUT UNTIL THE LOCAL FILESET MATCHES THE REF.

Do not trust a changed Unity Hub ref, a reused destination, or “Create a separate local copy” as proof of the requested checkout. The live run showed all three can leave/open unintended local state.

### Unreal

Prepared carrier exists, but real-host Ding is still open.

Current contacted prerequisite:
- Visual Studio 2022;
- Game development with C++ workload / Unreal C++ toolchain;
- sufficient storage headroom (installer displayed ~20.9 GB during contact).

UNREAL = STORAGE / TOOLCHAIN HOLD · REAL-HOST DING OPEN.

## 9. Runtime is the proof gate

For every host:

2. execute declared inputs;
3. verify each semantic consequence;
4. verify state values/deltas;
5. verify final bounded PASS;
6. record any mismatch as BUGG;
7. do not broaden the claim beyond observed contact.

RECIPIENT PROOF DOES NOT TRANSFER.

## 10. Runtime receipt

A receipt records:
- date;
- exact source body + SHA-256;
- host/version;
- carrier branch/commit/project;
- real_host = true;
- required semantic observations;
- PASS/FAIL/HOLD per observation;
- final bounded result;
- preserved HOLDs;
- route corrections;
- claim ceiling.

Proof-only screenshots can be redundified after their evidentiary value is faithfully transferred into receipts + GitHub/Library lineage, unless they remain the sole or uniquely valuable evidence.

## 11. Ding / BUGG gate

- static QA PASS = preparation;
- project opens = contact progress;
- runtime semantic PASS = bounded host Ding;
- mismatch/stall/error = BUGG and correction;
- plausible success = no claim.

NO DING, NO CLAIM.
CONTACT BEFORE CROWN.
