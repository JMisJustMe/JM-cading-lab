**Status of this document:** IMPLEMENTATION CONTRACT / PRE-BUILD

## 0. Governing decision

The Crown Pass is **not** a generic redesign and **not** a replacement application.

It mounts over the proved v0.1 body through the law:

> RESTORE BEFORE REWRITE. CONNECT WITHOUT FLATTENING. EXTEND WITHOUT ERASING.

The v0.1 website/PWA/APK remains the recovery checkpoint. The Crown Pass may change presentation, runtime organs, storage and room behaviours, but it must preserve the source route, route identity, traceability and recovery path.

The body is accepted only when the following route is visible and testable:

```text
SOURCE
→ JM CODING BODY
→ VISUAL ORGAN
→ CONTACT
→ READABLE STATE CHANGE
→ CONSEQUENCE
→ TRACE
→ RECOVERY
→ DING / RECEIPT
```

No graphic effect earns inclusion merely because it looks impressive. Every effect must have a named route-function.

# 2. Central visual laws

## 2.1 Protected crown field

The active room’s visual world is the dominant surface. It must not feel like a small demo canvas placed inside a generic webpage.

**Acceptance rule**

- on 412×915, the protected visual field must remain at least 300 CSS pixels high in the primary operating state;
- primary action and recovery remain visible without vertical page scrolling;
- temporary notices may not cover the principal interaction region or primary action.

## 2.2 Shared house, distinct rooms

Every room inherits common identity, spacing, receipt and control laws. Each room receives its own atmosphere, materials, motion species and framing behaviour.

Mesh does not mean merge.

## 2.3 Meaningful depth

Depth is divided into three governed planes:

```text
BACKGROUND = field memory / atmosphere
MIDGROUND = active structure / relation
FOREGROUND = contact / consequence / receipt
```

Glow, blur and parallax must state which plane a body occupies.

## 2.4 Consequential contact

Every interactive control must produce at least one of:

- visible field change;
- state label change;
- route change;
- trace event;
- exportable result;
- recoverable history point.

Controls with no consequence are defects.

## 2.5 Composition without erasure

MUM may combine source bodies but must retain:

- source-body name;
- source-body type;
- layer order;
- opacity / blend / transform state;
- independent visibility;
- independent removal;
- trace link to creation source.

Flattening is allowed only as an explicit exported derivative. The editable composition remains layered.

## 2.6 Motion discipline

Motion may indicate:

- active field;
- contact pressure;
- state transition;
- route movement;
- capture / export consequence;
- background life.

Motion may not obscure reading, simulate activity when nothing changes, or continue aggressively under reduced-motion mode.

## 2.7 Alert discipline

Notices use a three-tier body:

```text
TRACE CHIP — low priority, transient
ACTION NOTICE — requires one user action
FAULT HOLD — blocks only the failed route, never the whole app unnecessarily
```

The former large centre toast is prohibited on phone operating surfaces.

# 3. 128 actual-viewport architecture

`128` means the whole currently available visible body. `1–5` is priority and compression order, not five stacked bands.

## 3.1 Priority order

1. compact identity / state;
2. protected playable or visual world;
3. movement / manipulation contact;
4. actions;
5. always-reachable recovery and secondary tools.

## 3.2 Compression behaviours

When height pressure increases:

- identity subtitle collapses before identity disappears;
- route labels compress before the route system becomes unreachable;
- explanatory prose collapses into a revealable note;
- controls become a compact ContactBand;
- tools replace the contact field through tabs or drawers rather than extending below it;
- the recovery body never disappears.

## 3.3 Native-navigation guard

The runtime must measure `visualViewport` when available and reserve safe-area/native-navigation space. The body may not rely only on `100vh`.

## 3.4 Surface proof sizes

Required minimum proof matrix:

```text
412×915 Android touch
360×800 compact Android touch
768×1024 tablet portrait
1366×768 laptop
1440×900 desktop
```

No horizontal document overflow is permitted at any proof size.

# 7. Storage and session architecture

The `Local store is full` condition is a real route fault and must be redesigned.

## 7.1 Storage split

### `localStorage`

Only compact, replaceable state:

- active route;
- preferences;
- sliders / toggles;
- IDs and references;
- compact trace tail;
- recovery pointer.

### `IndexedDB`

Large or numerous bodies:

- imported images;
- captured video frames;
- MUM layer assets;
- Story thumbnails;
- session snapshots;
- export staging.

### Memory-only

- current video object URL;
- transient render buffers;
- animation particles;
- temporary compare state.

## 7.2 Quota-pressure behaviour

When persistence fails:

1. current work remains alive in memory;
2. large automatic snapshots stop;
3. a compact ActionNotice appears outside the crown field;
4. user receives `EXPORT SESSION`, `TRIM OLD SNAPSHOTS`, and `CONTINUE MEMORY-ONLY` routes;
5. a trace event records the fault and chosen recovery;
6. no repeated toast storm.

## 7.3 Session body

Canonical extension: `.jmvisual`

Minimum package:

```json
{
  "schema": "jm.visual.session/0.2",
  "identity": {},
  "state": {},
  "rooms": {},
  "layers": [],
  "story": [],
  "assetManifest": [],
  "traceTail": [],
  "receipts": [],
  "claimBoundary": ""
}
```

Binary assets may be embedded for a bounded single-file export or carried in a ZIP package with manifest hashes.

# 11. Accessibility contract

- all primary controls keyboard reachable;
- visible focus uses room accent and shape, not colour only;
- reduced motion retains state meaning;
- text contrast remains readable over active fields;
- canvas bodies provide nearby textual state / purpose;
- touch targets aim for 44 CSS pixels minimum where the actual viewport permits;
- no information is available only through hover;
- screen readers receive route name, room state and principal action;
- media remains local unless a later route explicitly states otherwise.

---

# 12. Performance contract

## Frame budget

- visual fields target smooth interaction on mid-range Android;
- particle density scales with measured field area and reduced-performance state;
- hidden rooms stop animation loops;
- background animation suspends when document is hidden;
- canvas DPR is capped;
- image treatment avoids repeated full-resolution redraw during slider drag;
- Story and Vault use thumbnails rather than full assets in list views.

## Memory budget

- revoke replaced object URLs;
- cap Story and trace rendering windows;
- release temporary capture canvases;
- do not persist particle state;
- large media never enters `localStorage`.

# 14. Proof and Ding contract

## 14.1 Static gates

- JavaScript syntax;
- JSON validity;
- Cading declarations present;
- required files present;
- no duplicate IDs;
- room profiles and HTML route IDs agree.

## 14.2 Browser gates

At each required viewport:

- actual viewport equals requested viewport;
- zero horizontal document overflow;
- protected crown field meets minimum size;
- primary contact and recovery visible;
- every route opens;
- no page errors;
- hidden rooms do not visibly animate;
- TraceBox opens and closes;
- notices avoid the crown centre and primary action.

## 14.3 Behaviour gates

- Illusion prediction → reveal → compare → trace;
- Image load → treatment → compare → export;
- Video load → step / trim → capture → Story;
- Motion preset change → parameter change → hold / resume;
- Forge inputs → formed body → copy / Story;
- MUM add bodies → reorder / transform → capture → Story;
- Story reorder / caption → HTML and JSON export;
- Vault export → clear → import → state restoration;
- storage fault simulation → memory preservation → export recovery;
- recovery returns last safe state without destroying source.

## 14.4 Visual proof gates

Screenshot set:

```text
portal desktop / phone
illusion predict / reveal
image source / treatment compare
video loaded / frame capture
motion full / reduced motion
forge input / formed body
MUM editing / capture consequence
story populated / exported
vault fault hold / Ding receipt
```

## 14.5 Ding boundary

A Crown Pass Ding may say:

> The named room routes, viewport fit, contact consequences, session recovery and exports passed the recorded gates.

It may not say:

- final universal visual system;
- full professional editor;
- production Play Store release;
- crowned body;
- proof of perceptual theory beyond the bounded experiments.

# 16. Definition of done

The Crown Pass first body is done only when:

- all nine rooms share one governed OneBody state and trace;
- all rooms have distinct visual profiles;
- MUM preserves editable source layers;
- the storage-full route no longer blocks or covers the visual field;
- session export/import restores the working state;
- the whole first viewport remains usable on tested Android sizes;
- no primary route requires document scrolling during normal operation;
- graphics demonstrate depth, material and meaningful motion;
- the user can inspect a quick HTML route before APK installation;
- browser gates and visual screenshot review pass;
- an Android debug APK compiles from the exact proved body;
- receipts state their claim boundaries accurately;
- v0.1 remains recoverable.
